# 実装計画: Conductor 完了時のセッション上レポート表示

## 概要

Conductor がタスク完了時に CONDUCTOR_DONE を送信する直前に、セッション画面上に「勘所レポート」を表示する。summary.md（詳細な作業ログ）とは別に、ユーザーが一目で「何が起きたか」を把握できる簡潔なレポートを出力する。

## 変更方針

テンプレートへのプロンプト追記のみ。Manager daemon やコードの変更は不要。

## 変更内容

### 1. `skills/cmux-team/templates/conductor-role.md` — 完了時の処理セクション

**変更箇所:** L158〜207「完了時の処理」セクション

**変更内容:** ステップ 7（close-task）とステップ 8（CONDUCTOR_DONE）の間に、新ステップ「完了レポートを表示する」を挿入する。ステップ番号を振り直す（8→完了レポート、9→CONDUCTOR_DONE、10→プロンプトに戻る）。

**追加テキスト（ステップ 8 として挿入）:**

```markdown
8. **完了レポートをセッション上に表示する** — CONDUCTOR_DONE の前に、以下の形式で勘所を出力する。該当しない項目は省略し、該当する項目だけを簡潔に書く:
   ```
   ── 完了レポート: <タスク概要（1行）> ──

   【設計判断】複数の選択肢があった場合、何を選びなぜ選んだか
   【試行錯誤】エラーや失敗が発生した場合、何が起きてどう対処したか
   【自己判断】タスク指示が曖昧で自分で判断した箇所
   【懸念・残課題】残った課題や確認が必要な点
   【成果】マージコミット or PR URL、主な変更点（1-2行）

   ────────────────────────
   ```
   注意:
   - 作業ログの羅列（変更ファイル一覧、コマンド履歴、Agent ごとの作業記録）は書かない。それらは summary.md の役割
   - 各項目は 1〜3 行に収める。全体で 15 行以内を目安とする
   - 該当しない項目は見出しごと省略する（空の項目を残さない）
   - このレポートは次タスクの /clear で消えて構わない
```

**変更後の完了時の処理セクション全体:**

```markdown

   （...既存のまま...）

6. worktree を削除する:
   （...既存のまま...）
7. タスクを close する:
   （...既存のまま...）
8. **完了レポートをセッション上に表示する** — （上記の追加テキスト）

### 2. `skills/cmux-team/templates/conductor-task.md` — 完了通知セクション

**変更箇所:** L37〜42「完了通知」セクション

**変更内容:** CONDUCTOR_DONE の前に、完了レポート表示の指示を追加する。conductor-role.md に詳細があるため、ここでは簡潔なリマインダーに留める。

**変更後のテキスト:**

```markdown
## 完了通知

全ての処理が完了したら:

1. セッション上に完了レポートを表示する（conductor-role.md「完了時の処理」ステップ 8 参照。設計判断・試行錯誤・自己判断・懸念・成果の勘所を簡潔に出力）
2. 完了通知を送信する:
   ```bash
   cmux-team send CONDUCTOR_DONE --surface $CMUX_SURFACE --success true
   ```
```

## 既存の流れとの整合性

| ステップ | 既存 | 変更後 | 影響 |
|---------|------|--------|------|
| summary.md 書き出し | ステップ 5 | ステップ 5（変更なし） | なし |
| close-task | ステップ 7 | ステップ 7（変更なし） | なし |
| **完了レポート表示** | — | **ステップ 8（新規）** | 追加 |
| CONDUCTOR_DONE | ステップ 8 | ステップ 9（番号変更のみ） | なし |
| プロンプトに戻る | ステップ 9 | ステップ 10（番号変更のみ） | なし |

- summary.md（詳細ログ）とレポート（勘所のみ）は役割が明確に分離されている
- レポートはテキスト出力のみで、ファイル書き出しやコマンド実行を伴わない
- CONDUCTOR_DONE の前なので、daemon のリセット処理（/clear）で自然に消える
- conductor-task.md にもリマインダーを入れることで、タスク割り当て時のプロンプトからも見えるようにする
