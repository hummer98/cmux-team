## 追加チェック

### 修正で新たな矛盾・抜け漏れが発生していないか

- ✅ **§2 と §3 の整合**: T104 を §2 にも §3 にも含めない方針で統一済み（Critical 修正方針 (a)）。§2 のコミット数 64 件はフィルタ `skills/ commands/ bin/ package.json .claude-plugin/` に基づくため、`.claude/settings.json` を対象外とするのは自然であり、§2 のベースライン記述（L8）と矛盾しない。
- ✅ **§4 Step 1 要確認リストと §3 マトリクスの整合**: 前回指摘した 4 項目（`.team/queue/` 存在、テンプレート数 14、05 の queue.ts 記載削除、planner.md {{OUTPUT_DIR}} 使用）がすべて §3 マトリクス側に確定事実として移動され、§4 Step 1 の要確認リスト（L120-126）には「※ 以下は Design Review を経て確定事実として §3 マトリクスに取り込み済み（要確認から除外）」として除外済みであることが明記されている。除外された項目名と §3 の記述が一致しており、Implementer がどちらを信じるべきか迷わない構造。
- ✅ **T078 削除の波及確認**: §2 feat 表、§2 arch 表、§3 06 行、付録のいずれにも T078 は残っていない。grep 的な置換漏れなし。
- ✅ **完了条件と §3 マトリクスの整合**: §5 完了条件 3 項目目を「節単位でレビュー可能な粒度」に緩和しても、§3 マトリクスで「05 が最大変更ファイル」と明示されているため Implementer が粒度を判断する基準は維持されている。
- ✅ **冒頭コメントの配置**: L3 の HTML コメント形式 `<!-- Critical 修正方針: ... -->` は Markdown 出力時に非表示になるが、Implementer が plan.md を「読む」前提では十分可視。レビュー観点（「plan.md 冒頭に Critical 修正方針が 1 行で記載されているか」）を満たす。必要なら後段で HTML コメントではなく通常の段落に昇格する選択肢もあるが、「方針が記録されていれば可」なので現状で approve する。
