## タスク
## 目的

Manager の TUI ダッシュボード（dashboard.tsx）が起動シーケンスの最後に表示されている。これをインフラ準備直後に起動し、Conductor/Master の起動進捗は TUI 上（ジャーナル）で表示する。

## 現状の起動順序（main.ts cmdStart）

1. createDaemon + initSourceWatcher + initFileWatcher
2. initInfra
3. ロギングプロキシ起動
4. initializeLayout（Conductor ペイン作成 + Claude 起動）
5. startMaster
6. startDashboard ← 最後

## 変更方針

### console.log を廃止
- cmdStart 内の全 console.log を削除し、manager.log（log() 関数）に統一する
- TUI 起動後は console.log は使えないので、起動進捗もすべて log() で記録

### TUI 早期表示
- プロキシ起動後（ステップ 3 の後）に startDashboard を呼ぶ
- initializeLayout と startMaster は TUI 表示中にバックグラウンドで実行
- TUI のジャーナル/ログタブで起動進捗が確認できる

### 起動ステータス表示（任意）
- DaemonState に起動フェーズを示すフィールドを追加してもよい（例: bootPhase: 'infra' | 'conductors' | 'master' | 'ready'）
- ヘッダーの RUNNING 表示を起動中は STARTING にするなど

## 対象ファイル
- skills/cmux-team/manager/main.ts（cmdStart 関数）
- skills/cmux-team/manager/dashboard.tsx（必要に応じて起動状態表示）

## 注意
- startDashboard に渡す scheduleRefresh は initializeLayout/startMaster の進捗が state に反映されるたびに呼ぶ必要がある
- シグナルハンドリング（SIGINT/SIGTERM）は TUI 起動後に設定すること
- ダッシュボードの onReload / onQuit / onFullQuit コールバックは既存のまま維持
